# ADR-005: الـ Backend مصدر الحقيقة الوحيد؛ Flutter عميل ذكي

## القرار
كل منطق أعمال (سير عمل، صلاحيات، قواعد تحقّق، قرارات نشر/اعتماد) يبقى **حصرًا** في الـ Backend. تطبيق
Flutter لا يعيد تنفيذه، لا يفترضه، ولا يُقصِّره — فقط يعرضه ويجمع البيانات اللازمة له عبر الـ API
الموثَّق.

## السبب
قرار منتج صريح من صاحب المنتج: منع ازدواجية المنطق بين لوحة التحكم (الويب) والموبايل، ومنع الانجراف
السلوكي التدريجي بين الاثنين بمرور الوقت — أي "مصدر حقيقة ثانٍ" ولو صغير يبدأ متطابقًا وينحرف حتمًا
مع الصيانة المنفصلة.

## البدائل المرفوضة
- **نسخ/تكرار منطق سير العمل أو التحقق على الموبايل** لتحسين الاستجابة الفورية أو دعم Optimistic UI
  معقّد — كل حالة كهذه تخلق مصدر حقيقة ثانٍ عرضة للانحراف عن الأول، ولو بدت مكسبًا في تجربة الاستخدام
  قصير المدى.

## الأثر
هذا هو **القيد الحاكم لكل قرار معماري لاحق** في هذا المشروع — أي اقتراح يخالفه، حتى لو كان تقنيًا
أفضل بمعزل، يُرفض بحكم هذا المبدأ وحده. كل ADR أخرى في هذا المجلد (لا سيّما ADR-003 وADR-004) امتداد
مباشر له.
