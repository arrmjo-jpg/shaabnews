# ADR-007: ليس Offline-First

## القرار
لا تخزين محلي حقيقي للكتابة، لا قاعدة بيانات محلية، لا مزامنة ثنائية الاتجاه في V1. المطلوب فقط
تعامل ذكي مع شبكة ضعيفة/غير مستقرة: إعادة محاولة محكومة بقواعد (ADR الخاص بـ Retry ضمن
`02-API-LAYER-AND-ERROR-HANDLING.md`)، ورفع خلفي يستمر أثناء بقاء التطبيق مفتوحًا فقط.

## السبب
قرار منتج صريح: "لا أهدف إلى بناء Offline-First في الإصدار الأول... المطلوب أن يعمل التطبيق بكفاءة
مع شبكات الهاتف الضعيفة وغير المستقرة." تعقيد المزامنة ثنائية الاتجاه الحقيقية مرتفع جدًا هندسيًا
(حل تعارضات، طابور عمليات معلَّقة، إعادة تشغيل بعد فشل جزئي) مقابل قيمة غير مؤكَّدة الحاجة الفعلية بعد
— لا دليل بعد أن فريق التحرير يعمل لساعات طويلة بلا أي اتصال إطلاقًا.

## البدائل المرفوضة
- **قاعدة بيانات محلية (`drift`/`hive`) + طابور مزامنة كامل من اليوم الأول** — استثمار هندسي كبير
  لسيناريو استخدام لم يثبت أنه شائع فعليًا، على حساب سرعة إطلاق حلقة العمل الأساسية (`00-VISION-AND-SCOPE.md`).

## الأثر
لا `drift`/`hive`/`isar` في V1 (راجع Package Baseline لتفاصيل مخاطر صيانة هذه الحزم أيضًا). استئناف
الرفع بعد إغلاق التطبيق بالكامل أو إعادة تشغيل الجهاز خارج النطاق كذلك. يُعاد فتح هذا القرار فقط إن
ظهرت حاجة تشغيلية فعلية موثَّقة، لا كافتراض مسبق.
