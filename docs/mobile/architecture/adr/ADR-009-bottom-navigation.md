# ADR-009: Bottom Navigation Bar كنمط التنقّل الرئيسي

## القرار
حُسم القرار المفتوح عمدًا في `01-NAVIGATION-AND-STATE.md` §١: **Bottom Navigation Bar** بخمس وجهات
نظيرة (الرئيسية/الأخبار/الريلز/الفيديوهات/الإعدادات)، عبر `ShellRoute` واحد في `go_router` يحيط بها
جميعًا.

## السبب
القرار تأجَّل عمدًا حتى لحظة التنفيذ الفعلي (Sprint 2) لتفادي تقييد التصميم مبكرًا (راجع
`docs/mobile/requirements/05-UX-SCREENS-AND-SETTINGS.md` §٣). عند الوصول لهذه اللحظة فعليًا: الوجهات
الخمس **نظيرة** (لا تسلسل هرمي بينها، ينتقل المستخدم بينها باستمرار أثناء الاستخدام اليومي)، والفلسفة
الحاكمة "أداة سريعة تركّز على الإجراء" (`00-VISION-AND-SCOPE.md` §١) تفضّل التنقّل بلمسة واحدة مباشرة
(Bottom Nav) على فتح قائمة جانبية بلمستين (Drawer) لكل تبديل قسم.

## البدائل المرفوضة
- **Drawer** — مناسب لعدد وجهات أكبر (>5) أو وجهات ثانوية غير نظيرة؛ يضيف احتكاكًا (لمسة إضافية) لكل
  تبديل بين الأقسام الخمسة التي يُستخدَم التطبيق للتنقّل بينها باستمرار.

## الأثر
`AppShell` واحد (`core/router` أو `core/widgets`) يحيط بمحتوى كل تبويب عبر `ShellRoute`، يحافظ على
حالة كل تبويب مستقلة (`IndexedStack` أو ما يعادله) عند التبديل. البنية الهيكلية الموضوعة أصلاً في
`01-NAVIGATION-AND-STATE.md` (مسارات مسمّاة مثل `/articles/:id`) لم تتغيّر — فقط الغلاف البصري حولها
تحدَّد الآن.
